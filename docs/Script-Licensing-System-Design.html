1. Overview

This document outlines the complete licensing system for selling scripts on Zenorar Marketplace.

Product Types Covered

  • Web Scripts (PHP, Node.js, Python, etc.)
  • Browser Extensions (Chrome, Firefox, etc.)
  • Mobile Apps (iOS, Android, React Native, Flutter)
  • Desktop Apps (Electron, native apps)

Core Principles

  • License validation without requiring constant internet
  • Tamper-proof license verification
  • Support duration tracking
  • Domain/identifier binding
  • Anti-piracy measures

License Restrictions

Normal & Extended License:

  • Cannot be resold or redistributed
  • Cannot be used in SaaS products (unless explicitly allowed)

  • Suitable for agencies managing multiple client sites
  • Cannot be resold or redistributed

3.2 License Key System

Format: ZNRSCR-XXXX-XXXX-XXXX-XXXX

function generateLicenseKey(orderId, productId) {
  const prefix = 'ZNRSCR';
  const data = `${orderId}-${productId}-${Date.now()}`;
  const hash = crypto.createHash('sha256').update(data).digest('hex');

  // Format: ZNRSCR-XXXX-XXXX-XXXX-XXXX
  const segments = [];
  for (let i = 0; i < 4; i++) {
    segments.push(hash.substring(i * 4, (i + 1) * 4).toUpperCase());
  }

  return `${prefix}-${segments.join('-')}`;
}

3.3 Watermarking (Buyer Identification)

Inject unique buyer identifiers into downloaded code:

/*
 * Licensed to: john@example.com
 * License Key: ZNRSCR-A1B2-C3D4-E5F6-G7H8
 * Purchase Date: 2026-02-24
 *
 * Unauthorized distribution is prohibited.
 * Trace ID: 8f4a2b1c-9d3e-4f5a-b6c7-d8e9f0a1b2c3
 */

Note: If a pirated copy is found, the trace ID can identify the source buyer.

4. License Validation

4.1 Online Validation (Phone-Home)

Best for web apps that have internet access:

const LICENSE = {
  key: "ZNRSCR-XXXX-XXXX-XXXX-XXXX",
  purchaseDate: "2026-02-24",
  supportExpires: "2026-08-24"
};

async function verifyLicense() {
  try {
    const response = await fetch('https://api.zenorar.com/licenses/verify', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        key: LICENSE.key,
        domain: window.location.hostname
      })
    });

    const data = await response.json();

    if (!data.valid) {
      handleInvalidLicense(data.reason);
      return false;
    }

    return true;
  } catch (error) {
    // Network error - use offline validation
    return verifyOffline();
  }
}

// Run on startup
verifyLicense();

// Run periodically (every 24 hours)
setInterval(verifyLicense, 24 * 60 * 60 * 1000);

4.2 Offline Validation (Signed License)

For scripts that may not have internet access, use cryptographically signed licenses:

How it works:

  1. Server signs license data with a private key
  2. Script contains the public key (safe to expose)
  3. Script verifies the signature - if data was tampered, signature fails
  4. User cannot change expiration date without invalidating signature

4.3 Hybrid Validation (Recommended)

Combine online and offline methods with a grace period:

async function validateLicense() {
  // Try online validation first
  try {
    const online = await onlineValidation();
    if (online.valid) {
      localStorage.setItem('lastVerified', new Date().toISOString());
      return true;
    }
    return false;
  } catch (networkError) {
    // Fallback to offline validation with grace period
    const lastVerified = localStorage.getItem('lastVerified');
    const daysSince = daysBetween(new Date(lastVerified), new Date());

    if (daysSince < LICENSE.gracePeriod) {
      return verifySignedLicense(LICENSE);
    }

    showError('Please connect to internet to verify license');
    return false;
  }
}

6.2 Recommended: Cloudflare R2

Why Cloudflare R2 is the best choice:

  1. Zero Egress Fees - Downloads are free, regardless of file size or frequency
  2. S3-Compatible API - Uses standard AWS SDK, easy migration if needed
  3. Built-in CDN - Fast global delivery without extra configuration
  4. Cost Predictable - Only pay for storage, not usage patterns
  5. Generous Free Tier - 10GB free storage, 1M requests/month
  6. Strong Security - Private buckets, signed URLs, access controls

6.5 Security Measures

┌─────────────────────────────────────────────────────────┐ │ SECURITY LAYERS │ ├─────────────────────────────────────────────────────────┤ │ Layer 1: Storage Security │ │ ├── Private R2 bucket (no public access) │ │ ├── Access keys in environment variables │ │ └── Bucket-level access controls │ ├─────────────────────────────────────────────────────────┤ │ Layer 2: Access Control │ │ ├── Authentication required (JWT token) │ │ ├── Ownership verification (user must own product) │ │ └── Admin-only upload permissions │ ├─────────────────────────────────────────────────────────┤ │ Layer 3: Download Security │ │ ├── Signed URLs with 1-hour expiry │ │ ├── One-time download tokens (optional) │ │ └── Rate limiting per user │ ├─────────────────────────────────────────────────────────┤ │ Layer 4: File Integrity │ │ ├── SHA-256 hash stored on upload │ │ ├── Hash verification on download │ │ └── Version tracking and changelog │ ├─────────────────────────────────────────────────────────┤ │ Layer 5: Audit & Monitoring │ │ ├── All downloads logged (IP, user agent, timestamp) │ │ ├── Failed access attempts recorded │ │ └── Anomaly detection (unusual patterns) │ └─────────────────────────────────────────────────────────┘

Signed URL Security

Signed URLs ensure:

  • Time-Limited Access - URLs expire after 1 hour
  • Tamper-Proof - URL signature verified by R2
  • No Direct File Access - Files cannot be accessed without valid signature
  • Revocable - URLs can be invalidated by changing signing keys

12. Gift Card Storage & Management System

12.1 Overview

The gift card system handles two types of cards:

  • Third-Party Cards - Steam, PlayStation, iTunes, Amazon, etc. (reselling actual codes)
  • Store Credit Cards - Zenorar gift cards that add wallet balance

Key Difference from Scripts:

Scripts are files stored in R2 and delivered via signed URLs. Gift cards are encrypted code strings stored in the database.

12.2 System Architecture

Third-Party Cards Flow

IMPORT: Admin → CSV Upload → Validate → Encrypt → Database PURCHASE: User → Pay → Reserve Code → Complete → Decrypt → Deliver DELIVERY: Email + Library Page + Copy Button

Store Credit Cards Flow

PURCHASE: User → Pay → Generate Code → Store in DB GIFT: Buyer → Pay → Send to Recipient → Recipient Redeems REDEEM: User → Enter Code → Add to Wallet Balance

12.4 Encryption System

AES-256-GCM Encryption:

  • All third-party gift card codes encrypted at rest
  • Unique IV (initialization vector) per code
  • Authentication tag ensures integrity
  • Only decrypted when delivered to buyer
// Encryption format: iv:authTag:encryptedData (all base64)
encrypt("STEAM-XXXX-YYYY") → "abc123...:def456...:ghi789..."

// Environment variable (64 hex characters = 32 bytes)
GIFT_CARD_ENCRYPTION_KEY=a1b2c3d4e5f6...

12.6 Purchase Flow

Third-Party Card Purchase

Step Action Status Change
1 User adds gift card to cart -
2 At checkout: Reserve code (database transaction) available → reserved
3 User completes payment -
4 On success: Mark sold, decrypt, email code reserved → sold
5 If payment fails (15 min timeout): Release reserved → available

Gift-Sending Flow (Store Credit)

  1. Buyer selects "Send as Gift"
  2. Enters recipient email, name, optional message
  3. Completes payment
  4. System generates code: ZNR-XXXX-XXXX-XXXX
  5. Email sent to recipient with redemption link
  6. Recipient logs in/creates account and redeems
  7. Balance added to recipient's wallet

13. eSIM System - Sourcing, Integration & Delivery

13.1 Overview

An eSIM (embedded SIM) is a digital SIM that allows users to activate a mobile data plan without a physical SIM card. Users scan a QR code to install the eSIM profile on their device.

Business Model

WHOLESALE PROVIDER (Airalo, eSIM Go, etc.) │ │ Bulk pricing: $5 for 5GB plan ▼ YOUR PLATFORM (Zenorar) │ │ Retail price: $8 for 5GB plan (60% markup) ▼ CUSTOMER │ │ Receives: QR code + activation instructions ▼ DEVICE (iPhone/Android) Scans QR → Installs eSIM → Has mobile data

Key Business Metrics:

  • Wholesale cost: $3-7 per plan (varies by data amount and region)
  • Retail price: $5-20 per plan
  • Typical margin: 40-60%
  • Delivery cost: $0 (instant digital delivery)

14. Virtual Numbers System - Sourcing, Integration & Delivery

14.1 Overview

A virtual phone number (DID) is a phone number not tied to a physical phone line. It can receive SMS/calls and forward them to any destination.

Use Cases

  • Privacy: Temporary numbers for online signups
  • Business: Local presence in different countries
  • Verification: Receive SMS codes
  • Travel: Local number while abroad

Revenue Model

PROVIDER (Twilio, Vonage, Plivo) │ │ Monthly: $1-2/number + $0.01/SMS ▼ YOUR PLATFORM (Zenorar) │ │ Monthly: $5-15/number (subscription) │ OR: $3-10 for 1-day/7-day temporary ▼ CUSTOMER │ │ Gets: Phone number + SMS inbox + Call forwarding MARGIN: 300-500% on number rental

Recommended: Twilio - Best documentation, largest coverage, reliable delivery, easy API

Profit Example

  • You charge customer: $5/month
  • Gross margin: $4/month per number (400%)
